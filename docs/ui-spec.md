# Open Tutor: UI spec

Maps the approved Claude Design mock (`Open Tutor.dc.html`, v2) onto the real engine, item bank and
graph. Where the mock and the data disagree, the data wins and the difference is recorded here.

Decisions taken 2026-08-08: Path shows the **goal slice** in 7 stages; Blockers show the student's
**real failing step**; Sunday builds the **real engine** behind these screens with a seeded student.

---

| token | light | dark |
|---|---|---|
| `--page` | `#E8E5DE` | `#08090A` |
| `--bg` | `#F5F3EE` | `#101112` |
| `--card` | `#FFFFFF` | `#191B1C` |
| `--ink` | `#15130F` | `#F2F0EB` |
| `--muted` | `#6B6459` | `#98948B` |
| `--line` | `#E3DED4` | `#292C2D` |
| `--accent` | `#0E8C8C` | `#3FD8C8` |
| `--gold` | `#B5820E` | `#E0AE3C` |
| `--sunk` | `#EDEAE3` | `#151718` |

Type: **Schibsted Grotesk** for UI, **STIX Two Text** for all mathematics, **Noto Sans Devanagari**
for Hindi prose. Frame 390x844, radius 46. One accent colour, used only for "where you are now".
Gold is reserved for mastered and appears nowhere else.

**Four node states, distinguishable by shape as well as colour** (an accessibility requirement, not
a stylistic one): mastered = filled gold disc; learning = half-filled disc; now = pulsing accent
ring; locked = dashed grey ring.

Animations to keep: `pulse` (the frontier node), `arrive` (diagnosis reveal, 0.7s cubic-bezier),
`goldin` (node turning gold), `riseline` (spine growth on Complete), `blink` (thinking indicator).

## 2. Flow

```
Onboard ─→ [Today] ⇄ [Path] ⇄ [Blockers] ⇄ [You]          tab bar, always visible
              │                    │
              │                    └─ "Fix this" starts a targeted set
              │
              └─→ Solve ─┬─ typed answer ─────────────→ Result ─→ next problem, or Complete
                         └─ photo → Check ────────────→ Result
```

The solve flow is full screen, hides the tab bar, and has exactly one exit. **The step indicator is
2 dots for the typed path and 3 for the photo path**, not a fixed 3 as in the mock.

## 3. Screens and their real data contracts

### Onboarding
One question, prefilled `How neural networks learn`, one button. Nothing else.
Data: none. The goal maps to `graph.target_node` (hardcoded for the demo).

### Tab 1, Today
Header `6 problems · 15 min`. Six cards, each one line of maths plus a reason chip.
Data: `selection.compose_daily_set(graph, states, items, now)` returns `SetEntry(item, slot, reason)`.
**The chip text is `SetEntry.reason`, already generated by the engine.** Chips in slot order:
`Blocker · <misconception>`, `Review`, `New · <node title>`, `On your path`.
The accent dot appears on blocker rows only.

### Tab 2, Path
Target card: `Gradient descent`, `N skills away`, `about D days at your pace`.
- **`N skills away` = count of ancestors of `target_node` that are not yet `mastered`.** The mock's
  "4" was a placeholder.
- `D` = remaining skills divided by the student's recent mastery rate, floored at 1 day.

Seven stages, derived from the node id namespace, not authored:

| stage | prefix |
|---|---|
| Algebra moves | `alg.` |
| Trig values | `trig.` |
| Limits | `lim.` |
| Derivative rules | `der.` |
| Multivariable | `mv.` |
| Optimisation | `opt.` |
| Gradient descent | `ai.` |

Only nodes in the **goal slice** are listed: the 26 ancestors of `ai.gradient-descent-step` plus the
target. A node outside the slice appears only if it currently holds a blocker. Ordered bottom to
top by stage depth; one stage expanded at a time; stage `count` is `mastered/total` within the slice;
stage `state` is the state of its least advanced node.

**The `needs:` chip is generated from `graph.prereqs(node)`, showing the first unmet prereq.** The
mock's hand-written `Chain rule needs: Quotient rule` is wrong under the current graph and must not
be copied.

### Tab 3, Blockers
One card per open misconception, ranked by frequency.
Data: `NodeState.misconceptions` plus the attempts that produced them.
- `name`: human-readable misconception, e.g. `Dropping negatives across brackets`
- `freq`: count of attempts carrying that tag, e.g. `4 times this week`
- **wrong/right pair: the student's own `failed_step` from the attempt, struck through, above the
  corrected line.** Requires persisting `failed_step` and a `corrected_step` on the attempt.
- `Fix this →` composes a set of items for that node only.

A blocker is **always actionable**, including when its node is `locked`. Locking gates new learning
only, so this tab never shows a "come back later" state.

### Tab 4, You
Streak, `skills mastered`, `accuracy this week`, language toggle, appearance toggle.
Data: mastered count and accuracy come from the attempt log. **Streak needs a `days with a completed
set` derivation; it is P2 and may show a placeholder for the demo.**

### Solve
Problem in STIX. Typed answer box. Photo button. Hints accordion, four rungs.
- Hints come from a per-node ladder; rung 2 is the rule in maths, rung 4 reveals the full solution
  **and offers an isomorphic twin**. The twin is generated by re-rendering the same `check` spec with
  different numbers, which costs no API call.
- Hint level is recorded on the attempt and reduces evidence weight, never XP.

### Check (photo path only)
`Here's what we read.` / `Tap any line to correct it.` Transcript lines, confirm button.
Data: Sarvam Vision output, split into lines. Corrections edit the text sent to diagnosis.
This screen is the error boundary: Vision inserted a spurious `^-` in one of four real samples.

### Result
Two stages.
1. **Instant**: `Incorrect` plus `Expected <answer>`, from `services.grading.grade`. The CAS decides,
   never the model.
2. **~3s later**: the diagnosis arrives with the `arrive` animation. Failing line highlighted in the
   work block. Consequence line naming the node that dropped. `Was this your mistake?` yes/no.

**Three Result states are needed, not one:**
- correct: verdict only, no diagnosis call at all
- correct but unsimplified: treated as correct, with a light "you can simplify further" note
- incorrect: the full designed state

Diagnosis is served from `data/demo/diagnosis_cache.json` when the work matches a cached entry, with
a live call as fallback. `seed` does not pin model output, so anything shown on stage is pre-computed.

### Complete
Spine grows, nodes turn gold, `Tomorrow starts with <focus>.`, `+N XP · M unlocked`.
Data: XP from `xp.xp_for` summed over the session; `M` = nodes that moved from locked to frontier;
focus = the top blocker for tomorrow's set.

## 5. Deliberately not built

Leaderboards, social, multi-goal, live graph compilation, accounts. All out of scope per the MVP plan.

## 6. Hindi coverage, stated honestly

All translation is hand-written. No model was used, so section 13's rule (never send notation
through a translator) holds by construction rather than by verification.

| content | Hindi coverage |
|---|---|
| node titles (37) | complete |
| UI strings (50) | complete |
| generated item stems (194) | complete, by template |
| misconception names and chip shorts (38) | complete |
| hint prose rungs (111) | **37 of 111**, covering 3 of 37 nodes fully |

The three nodes with complete hint ladders in Hindi are exactly the ones the demo touches:
`der.quotient-rule` (the live problem), `alg.sign-distribution` and `alg.fraction-arithmetic` (the
two blockers). Coverage is high per rung rather than per node because templated rungs are shared:
one translation covers every node that uses it.

**A rung with no Hindi falls back to English.** That is deliberate. Readable English beats a guessed
translation, and it beats a raw key absolutely.

Hint translations live in `data/i18n/hints_hi.json`, keyed by the English source string, NOT in
`data/content/hints.json`. That file is generated by `pipeline/build_hints.py` and its tests assert
it contains node ids only, so a translation stored there would be silently discarded by the next
build. The same applies to `misconceptions.json`: both tables must stay pure maps, with no metadata
keys sharing the namespace, because consumers iterate every key.

Rungs marked `is_math` are LaTeX and are never translated in any language.
